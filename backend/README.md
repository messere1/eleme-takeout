# 轻量级外卖服务平台 - 后端

天津大学软件学院软件工程（系列）综合实践项目的后端仓库。项目参考“饿了么”核心业务，提供面向前端的 REST API，并重点训练 TDD、分层架构与需求变更适配能力。

> 当前状态：项目初始化阶段，暂未开始业务代码开发。

## 课程信息

- 实践周期：2026-08-31 至 2026-09-20（共 3 周）
- 项目名称：轻量级外卖服务平台（仿饿了么）
- 开发方式：全程遵循 TDD（测试优先开发）
- 协作方式：Git 版本管理、小组协作、跨组交叉验收

## 后端职责

- 用户注册、登录、状态校验与个人信息维护
- 商家注册及开店、关店、临时闭店等状态管理
- 店铺、商品分类、商品、价格和库存管理
- 购物车增删改查
- 订单创建、列表查询与状态查询
- 统一响应、参数校验和全局异常处理
- 数据库设计、接口测试、回归测试和联调支持

## 计划技术栈

- Java + Spring Boot
- MyBatis 或 MyBatis-Plus
- MySQL 或 PostgreSQL
- JUnit 5 + MockMvc
- Postman 或 ApiFox

具体版本和二选一技术方案将在正式开发前由小组共同确认，并通过设计文档和 Git 记录留痕。

## 分层架构

```text
Controller  接收请求、参数校验、返回响应
    ↓
Service     核心业务规则与需求迭代
    ↓
Mapper/DAO  数据访问
    ↓
Entity      领域实体与数据表映射
```

Controller 不承载复杂业务逻辑；高频公共能力通过统一异常处理、统一响应结果和通用工具封装，降低需求变更带来的耦合。

## API 约定

- 接口统一使用 `/api/v1` 前缀。
- URI 使用资源名词，查询使用 `GET`，创建使用 `POST`，更新使用 `PUT/PATCH`，逻辑删除使用 `DELETE`。
- 登录、取消订单等明确业务动作允许采用动作型子路径。
- 使用标准 HTTP 状态码，并统一返回 `code`、`msg`、`data`。
- 分页、过滤和排序使用 Query 参数。

接口契约将在开发前由小组讨论确认，README 中的约定不替代正式 API 文档。

## TDD 与提交规范

每个接口和核心业务方法遵循以下顺序：

1. 分析需求并定义接口行为。
2. 编写正常、异常和边界场景测试。
3. 运行测试并确认失败。
4. 编写最小业务实现使测试通过。
5. 重构并执行全部回归测试。
6. 分阶段提交，保留“红 - 绿 - 重构”的 Git 证据。

课程目标要求核心业务接口测试覆盖率 100%，关键业务方法覆盖率不低于 90%，并留存测试类、测试报告、测试日志和需求迭代后的回归测试记录。

## 三周计划

| 阶段 | 时间 | 目标 |
| --- | --- | --- |
| 第 1 周 | 基础需求 | 搭建分层架构，完成用户、商家、店铺、商品、购物车和基础订单接口及测试 |
| 第 2 周 | 需求迭代 | 先补测试再实现变更，完成旧功能回归测试，避免大面积重构 |
| 第 3 周 | 完善验收 | 清理耦合与冗余，完成联调、全量测试、文档和交叉验收材料 |
