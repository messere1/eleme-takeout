## 3. 本轮新增覆盖

1. API 映射：公开店铺分页、分类商品分页、商品详情、独立价格修改、购物车 `POST/PATCH`、订单默认 20 条。
2. 业务边界：价格上限和小数精度、购物车用户隔离及重复加购超库存、订单唯一编号、金额精度、`TEMP_CLOSED` 禁止下单、时间反向区间、稳定排序。
3. 安全健壮性：401/403/404/409/500 的 `traceId`、通用异常兜底、无动态拼接 SQL、诊断文本不暴露密码和完整手机号。
4. 前端交互：主要页面错误状态、提交期间按钮禁用、V1.2 API 路径与订单状态/分页契约。

## 4. 尚待闭环

1. 店铺分页和商品分页/详情尚无业务入口，当前先由映射契约测试稳定报红；实现后需追加基于真实分页数据的集成测试。
2. 真实数据库并发与唯一约束、服务端日志采集仍需在相应实现和运行环境具备后执行。
3. 1280×720 浏览器测试待页面可运行后按 `phase-1-p0-srs-v1.2-test-cases.md` 留存截图和复现证据。
4. 覆盖率验收应在红灯修复、全量测试通过后生成，不能用当前失败运行宣称达标。

## 5. 后续回归规则

1. 功能负责人每修复一个缺陷，先运行对应失败测试，再运行同模块测试。
2. 修复提交不得删除、跳过或弱化既有断言；契约调整必须先评审并同步修改 SRS、接口文档和测试。
3. 最终执行前后端全量回归，目标为零失败、零未处理异常。
4. 测试专员维护用例、回归证据、缺陷和需求影响记录，不代写核心业务实现。
