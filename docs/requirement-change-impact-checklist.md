# 需求变更影响分析与回归清单

## 1. 变更登记

每次需求调整至少记录以下内容：

| 字段 | 内容 |
| --- | --- |
| 变更编号 | CR-日期-序号 |
| 关联需求 | FR-xxx |
| 变更摘要 | 说明新增、删除或修改的行为 |
| 接口影响 | 路径、方法、请求参数、响应结构、错误码 |
| 数据影响 | 表结构、约束、存量数据、事务边界 |
| 权限影响 | 用户角色、资源归属、未登录和越权行为 |
| 前端影响 | 页面、路由、组件、状态和提示文案 |
| 测试影响 | 新增、修改、废弃的测试类和场景 |
| 风险等级 | 高 / 中 / 低及理由 |

## 2. 测试实施顺序

1. 选择单个变更功能，明确可验证的验收条件。
2. 更新需求—测试追踪矩阵。
3. 编写并运行失败测试，确认失败原因与需求一致。
4. 单独提交失败测试，不混入业务实现。
5. 由功能负责人编写最小实现。
6. 运行目标测试、同模块测试和全量回归。
7. 单独提交实现；重构另行提交并再次回归。

## 3. 回归范围选择

| 变更模块 | 必跑测试 |
| --- | --- |
| 登录、JWT、安全配置 | Auth、User/Merchant 登录、SecurityIntegrationTest、全部受保护 Controller |
| 用户或商家资料 | 对应 Service/Controller、登录和资源归属测试 |
| 店铺、分类、商品 | Shop、Category、Product 全部测试；购物车可用性和下单测试 |
| 价格或库存 | Product、Cart、Order 全部测试；金额精度和库存回滚场景 |
| 购物车 | Cart 全部测试；OrderCreationServiceTest |
| 订单 | Order 全部测试；Cart 与 Product 库存相关测试 |
| 统一响应或异常处理 | 所有 Controller、SecurityIntegrationTest、ApiResponseTest、ValidationErrorTest |
| 前端路由或公共状态 | 全部前端测试和生产构建 |

## 4. 完成标准

- 新增测试能在旧行为上准确失败，并在目标实现后通过。
- 后端全量测试零失败，关键 Service 行覆盖率不低于 90%，核心 Controller 行覆盖率 100%。
- 前端全量测试零失败且生产构建成功。
- 不存在无追踪需求的测试，也不存在无测试覆盖的已实现 P0 需求。
- 测试报告、追踪矩阵和缺陷状态同步更新。
