## 2. V1.4 变更与影响

| 需求 | 变化 | 后端影响 | 前端影响 | 测试结论 |
| --- | --- | --- | --- | --- |
| 账户角色 | 增加 `ADMIN`；手机号按角色集合分别唯一 | 登录角色枚举、安全规则、管理员身份来源 | 登录角色选择、管理员路由保护 | 顾客/商家隔离已有覆盖；管理员能力红灯 |
| FR-022 | `CREATED → ACCEPTED → COMPLETED`，顾客也可确认完成 | 三个状态动作、所属权、并发条件更新 | 商家接单/完成、顾客确认按钮 | 现有实现与新增契约测试通过 |
| FR-023 | 管理员只读查看用户、商家账户列表 | 两个分页 GET 接口；禁止任何写操作；敏感字段脱敏 | 只读列表、加载/空/403/500 状态 | 红灯：当前无管理员模块 |
| FR-024 | 下单保存收货人、联系电话、地址快照 | 请求校验、持久化、查询响应、历史不可变性 | 三字段录入、默认值、提交防重、错误展示 | 红灯：当前只传递并保存地址 |
| 延期边界 | 支付、超时取消、退款、图片、注销、管理员写权限、配送不纳入本版 | 不应出现未约定状态或后台任务 | 不展示虚假的已支持入口 | 仅做边界检查，不要求实现 |

## 4. 功能负责人后续最小实现边界

以下内容不是本轮测试专员的实现任务，但属于关闭红灯的必要条件：

1. 将订单收货字段从单一 `address` 扩展为 `recipientName`、`recipientPhone`、`deliveryAddress`，完成校验、快照持久化和查询返回。
2. 新增管理员身份与两个只读分页接口，并明确禁止管理员写操作。
3. 前端购物车结算区增加收货人和联系电话；API 层不得丢弃请求体。
4. 新增管理员只读页面以及加载中、空数据、403、500 状态。

功能负责人应在独立实现提交中完成上述修改，不得删除、跳过或弱化本轮红灯测试。

## 5. 回归范围

实现提交后必须运行：后端 Auth、Security、User、Merchant、Order 全部测试；前端 Login、Cart、Orders、MerchantOrders、管理员页面及 API 契约测试；随后执行前后端全量回归、生产构建和 1280×720 浏览器检查。
