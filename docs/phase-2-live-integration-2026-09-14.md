# 第二阶段真实前后端联调记录（2026-09-14）

## 环境与范围

- 代码版本：本地 `main`，包含远端 PR #6 的四个新增接口和本地测试适配提交 `a8e53a9`。
- 隔离后端：`18081`，Spring Boot 使用测试类路径及一次性 H2 内存数据库；隔离前端：`5174`，Vite 代理到该后端。原 `8080/5173` 服务及共享 PostgreSQL 未用于写入测试。
- 浏览器：本机 Microsoft Edge，无头模式，视口 `1280×720`。登录页有内容、无 Vite 错误遮罩和页面脚本异常。
- 本轮只验证下述实际执行的场景；H2 结果不替代 PostgreSQL 事务、迁移和故障注入验收。

## 实测通过

1. `node scripts/isolated-four-interfaces.mjs`（环境变量 `TAKEOUT_FLOW_BASE=http://127.0.0.1:18081`）：30 次真实 HTTP 校验通过。包括两个商家和一个顾客注册登录、商家本店品类空集合/三项设置/重复设置、按品类筛选营业中店铺、跨商家隔离、无令牌 401、顾客越权 403、未知类别 400 且原关联不变；营业时间合法修改、非法时间 400 且旧值不变、他店和顾客越权 403；骑手注册 201、登录并访问工作队列、重复注册 409、非法注册 400。失败响应均有 `traceId`，未见堆栈或数据库信息。
2. `node frontend/scripts/isolated-browser-four-interfaces.mjs`：Edge 经 `5174` 页面完成商家注册并自动登录、在商家页保存营业时间、在资料页选择并保存两项经营类别、退出后以页面注册骑手并进入骑手工作台。实际网络记录包含 `POST /api/v1/merchants 201`、`PATCH /api/v1/shops/{id}/business-hours 200`、`GET/PUT /api/v1/merchant/shop/business-categories 200`、`POST /api/v1/riders 201`。浏览器无页面脚本异常。

首次 API 脚本将新注册且默认 `CLOSED` 的店铺用于公开品类筛选，结果为空。核对查询条件后确认属于测试前置条件错误；在脚本中先设置为 `OPEN` 后重跑通过，不记为产品缺陷。首次浏览器脚本使用了错误的 Element Plus 输入框定位，并尝试在商家已登录状态直接进入注册页；调整定位和先退出登录后，完整浏览器脚本通过，不记为产品缺陷。

## 尚未执行

测试文档原有 62 个“未通过、阻塞或待执行”用例不能由本轮 30 次 API 校验和一条浏览器链路整体转为“通过”。尤其是品类与营业时间的数据库中途失败/并发修改、骑手注册并发与持久化失败、订单支付超时竞争、旧数据库卷迁移、磁盘写满、完整四角色浏览器下单到退款流程，以及不同浏览器和窄视口矩阵，仍需独立前置数据或故障注入并逐项留证。本轮未修改 Word 测试文档中的原有状态。

## 复现入口

先在独立后端运行测试类路径和 H2 内存库，监听 `18081`，并以 `frontend/scripts/vite-integration.config.mjs` 启动 Vite `5174`。测试脚本限定本地隔离端口，不能指向共享 `8080`。完成后停止临时服务；内存数据库随进程销毁。
