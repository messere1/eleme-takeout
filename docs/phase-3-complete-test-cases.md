# 第二阶段完整测试用例基线（历史文件名保留）

## 1. 范围与状态

本清单覆盖 SRS V2.0 的全部正式需求。原 DR-001～DR-007 已在第二阶段评审中转为活动需求：平台内模拟支付、15 分钟自动取消、退款、图片上传、账号注销、管理员管理和骑手配送全部计入本阶段通过率，不再设置延期项。

状态：`自动化`表示已有可执行测试；`红灯`表示测试已执行且当前实现不满足；`人工/专项`表示需要浏览器、真实数据库、压力或恢复环境。

## 9. 第二阶段执行顺序

1. 先运行当前基线自动化测试并记录既有失败。
2. 单独运行本轮新增测试，确认红灯与需求缺口一致。
3. 功能负责人按单个需求提交最小实现，不与测试提交混合。
4. 每完成一个需求，运行目标测试、关联模块测试和全量回归。
5. 最后执行真实数据库事务故障、50 并发、5 分钟性能、三浏览器和全部视口专项测试。
